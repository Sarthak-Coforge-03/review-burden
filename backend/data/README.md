# Synthetic data

Generated by `backend/scripts/generate_synthetic_data.py` (stdlib only, fixed seed, deterministic). Do not edit by hand: change the script and rerun.

```bash
python backend/scripts/generate_synthetic_data.py   # from review-burden/
```

The script also verifies the data: an independent re-implementation of the flag rules must find exactly the planted problems below and nothing else, or it exits non-zero.

## Files

| File | Use |
|---|---|
| `developers.csv`, `pull_requests.csv`, `reviews.csv`, `review_comments.csv` | CSV import fixtures |
| `review_requests.csv` | Who was asked to review and when it was fulfilled (needed for `stale_backlog` and "review debt") |
| `seed.json` | Everything above in one ingest-shaped payload, plus `as_of` |
| `triage.json` | Triage the demo starts with (applied to flags after the engine runs) |
| `expected_flags.json` | Ground truth for rule tests and the seed smoke test |

Scale: 8 people (1 manager), 253 PRs over 12 weeks (13/week rising to 27/week), 351 reviews, 491 comments.

## Evaluate "as of" the data, not the wall clock

`as_of` is `2026-10-09T18:00:00Z`. Rules with windows or ages (`stale_backlog`, `load_concentration`, `repeat_pattern`) must use `as_of` as "now", otherwise the planted problems age out and the demo goes quiet. In the backend, get "now" from `backend.clock.now()`, never from `datetime.now()`; it returns this `as_of` unless the `AS_OF` environment variable overrides it.
